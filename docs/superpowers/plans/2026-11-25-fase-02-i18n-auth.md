# Fase 2 — i18n + Auth Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every UI string goes through Paraglide (locale in the URL, one JSON file per domain), and users can register, verify their email, sign in with email/password, Google, or OIDC, and reset their password, with each method switched on or off from `.env`.

**Architecture:** Paraglide compiles `src/lib/i18n/locales/{locale}/*.json` into typed message functions. `reroute` in `src/hooks.ts` strips the locale prefix, and `paraglideMiddleware` sets the request locale. Better Auth runs in-process: `svelteKitHandler` serves `/api/auth/*`, and pages call `auth.api.*` from form actions, so the auth pages work without client JS. The SSO rule (§6.1) is one pure function, called from Better Auth database hooks.

**Tech Stack:** `@inlang/paraglide-js` 3.2.2 + `@inlang/plugin-message-format` 4.6.2, `better-auth` 1.7.28 (CLI: `auth` 1.7.28), `nodemailer` 10.6.1, shadcn-svelte 1.8.1 (CLI), Tailwind v4, Zod 4.

**Spec:** `docs/superpowers/specs/2026-11-24-sveltekit-starter-design.md` (§6, §6.1, §10, §11, §13, §13a, §13c, §15)

## Global Constraints

- SvelteKit 3.4.x: config in `vite.config.ts` `sveltekit({...})`; imports use `#lib/...` / `#database/...` with explicit `.ts`; `$app/env/*` not `$env/*`; hook types from `@sveltejs/kit/hooks`; `event.request` is readonly (pass `{ ...event, request }` to `resolve`).
- Pin exact versions (no `^`), as in Phase 1. TypeScript stays 6.0.3, Vitest 5.1.0.
- Env is read only through `src/lib/server/core/config.ts` (`getConfig()`); app code never reads `process.env`. Build needs no secrets (keep everything lazy).
- Tables live in `database/schema/<domain>.ts` and are exported from `database/schema/index.ts`; `db.ts` builds its `schema` object from that barrel.
- Tests live in `tests/unit` (no DB), `tests/integration` (real `app_test`), `tests/e2e` (Playwright on the build). No tests next to source.
- Locales: `id` (default, no URL prefix) and `en` (`/en/...`). Locale files: one JSON per domain, same file names in every locale, each file has exactly one top-level key equal to its file name (`auth.json` → `{ "auth": { ... } }`). Messages are used as `m['auth.login.title']()`.
- No hard-coded UI copy in `.svelte` files or emails: every visible string is a message.
- Docs in Bahasa Indonesia, no phase labels, run through the `no-ai-slop` skill. Code, identifiers, commit messages in English.
- Commits: conventional, header ≤ 72 chars, no `Co-Authored-By`/AI attribution lines.
- Login error responses never echo input or reveal whether an email exists.

## Review Focus

1. Locale prefix vs. non-page routes: `/api/auth/*`, `/healthz`, and `/en/healthz`-style paths must not break; Better Auth callbacks are never localized. → Task 1 e2e + Task 3 integration.
2. `redirectTo` on `/login` is an open-redirect vector: only same-origin paths (`/x`, not `//x`, not `https://…`) are honored. → Task 7 unit test of `safeRedirect`.
3. `/login?error=<anything>` renders only a known message for known codes and a generic one otherwise; the raw value is never rendered. → Task 7 unit test of `loginErrorMessage`.
4. A user disabled after signing in loses access on the next request, not at session expiry. → Task 3 integration test.
5. Forgot-password answers identically for a known and an unknown email. → Task 7 e2e.
